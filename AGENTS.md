- Settings store nothing by default, and a row always shows what is on screen. Theme flips between light and dark and never gets a "System" entry: a press that lands on the OS scheme clears storage, per [Lea Verou](https://lea.verou.me/blog/2026/dark-mode-toggles/). Backdrop, Shape and the light and dark themes draw at random by default (the themes once per visit, from their own scheme); their rows mark a drawn value "(random)", and the first press stores it unchanged, so keeping what is on screen takes one press. "Random" joins their rotation, after the last value, only while a value is stored; choosing it clears storage and the row reads "(random)" again, so every press changes what the row says.
- The pixel backdrop is the npm package `@carterworks/pixel-backdrop` ([carterworks/pixel-backdrop](https://github.com/carterworks/pixel-backdrop)), pinned to an exact version, which knows nothing of the site and holds its own layers. The site reaches it only through the package's `exports`. `src/test/architecture.test.ts` holds this and the site's layers over it; never add to its `exceptions` or widen a layer's `imports` to make it pass without the owner's say, as that is the only thing keeping the layers apart.
- The limits in `scripts/budgets.mjs` are ratchets: lower one in the same commit when a change does less, and never raise one to make `pnpm budgets` pass without the owner's say, as each is an exact count with no margin to hide a regression in. The file's header has the full rule.
- A golden frame change must be deliberate: never update `src/components/pixel-backdrop/__snapshots__/golden.test.ts.snap` just to make the test pass, and say in the commit what changed on screen and why, as the digests are what notices a refactor changing what a toy shows.
- Frame rates from a phone count only over HTTPS, so measure with `pnpm perf:device`: over plain HTTP, Safari runs the page's JavaScript without a JIT, which once read 48 fps where the real site holds 60.
- Toys, shader passes and the elements' attributes, properties, methods and CSS custom properties change in the pixel-backdrop repo and reach the site through a release, by bumping the pinned version; a new toy also adds golden entries and script bytes here, as the tests and `pnpm budgets` say. `src/test/toy-canvas.ts` copies the package's soft canvas, which it does not ship, so keep the two in step.
- A theme is one entry in `DISPLAYS` in `src/components/pixel-backdrop/backdrop-displays.ts`: its scheme, the canvas's `base` and `ink`, the page's colours, and a `look` if it is a physical panel. The menus, the page's CSS, `theme-color`, the web manifest and the backdrop (through `follow-display.ts`) all read that list, so never restate a theme's colours elsewhere; a new theme also adds golden entries and its per-frame budgets, as the tests and `pnpm budgets` say.
